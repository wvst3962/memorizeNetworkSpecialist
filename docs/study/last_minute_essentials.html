1. まず番号を混同しない

IPプロトコル番号はIPv4ヘッダのProtocol値（IPv6ではNext Header値）、ポート番号はTCP/UDPで使う値、EtherTypeはEthernetフレーム内の識別値です。同じ「番号」でも場所が違います。

IPプロトコル番号：番号から名前を言う

番号 答え・役割
1 ICMP：IPv4のエラー通知や到達性確認
2 IGMP：IPv4マルチキャストの参加管理
6 TCP：確認応答・再送・順序制御
17 UDP：コネクションを張らない転送
47 GRE：トンネリング
50 / 51 ESP / AH：IPsecのペイロード保護 / 認証ヘッダ
58 ICMPv6：IPv6の制御、近隣探索にも使用
89 OSPF：リンクステート型の経路制御
103 PIM：IPマルチキャストの経路制御
112 VRRP：デフォルトゲートウェイの冗長化

OSPFの「89」と、BGPの「TCP/179」は別種の番号です。経路制御・VRRP

よく見るポート：サービスから番号を言う

サービス・用途 答え
SSH / DNS TCP/22 / UDP・TCP/53
DHCPサーバ / クライアント UDP/67 / UDP/68（H25午後I）
TFTP / NTP UDP/69 / UDP/123
HTTP / HTTPS TCP/80 / TCP/443（HTTP/3はUDP/443）
SMTP中継 / メール投稿（Submission） TCP/25 / TCP/587（H28午後I）
SNMP要求 / Trap UDP/161 / UDP/162
BGP TCP/179
IKE / NAT-T UDP/500 / UDP/4500
SIP / SIP over TLS 5060 / 5061（利用するトランスポートは構成で確認）
VXLAN UDP/4789

ポートは典型的な利用例です。番号だけで通信の安全性は決まりません。DHCP・SMTP・SNMP

EthernetのEtherType

値 答え
0x0800 / 0x0806 IPv4 / ARP
0x8100 / 0x86DD 802.1QのC-Tag / IPv6

2. IPアドレス・DNS・DHCP

問い 答え
同一LANで宛先IPv4アドレスからMACアドレスを知る ARP。自分のIPとMACを周囲へ通知するのは GARP（R1午後I）
他端末宛てのARP要求にルータが代理で応答する Proxy ARP
DHCPでアドレスを取得する4メッセージ DHCPDISCOVER → DHCPOFFER → DHCPREQUEST → DHCPACK（H25午後I）
DHCPサーバが別セグメントにあるとき、要求を転送する DHCPリレーエージェント（H25午後I）
DNSでホスト名→IPv4 / IPv6アドレス A / AAAA レコード
DNSでメール配送先 / 権威DNS / 別名 / 逆引き MX / NS / CNAME / PTR レコード（H21・R5午後）
MXが複数あるとき、配送優先度が高いのは Preference値が小さい方（R6午後II）
DNSキャッシュサーバと権威DNSの違い キャッシュDNSは名前解決を代行・保存し、権威DNSは担当ゾーンの正式なデータを返す

DNSレコード・GARP・Proxy ARP

3. 経路制御・冗長化

問い 答え
OSPFの経路計算の基礎 LSDB（リンク状態データベース）を共有し、ダイクストラ法で最短経路を計算（R3午後I）
OSPFの中心となるエリア エリア0（バックボーンエリア）
BGPの4メッセージを用途順に言う OPEN：ピア開始、UPDATE：経路広告・撤回、KEEPALIVE：維持、NOTIFICATION：エラー（R5午後II）
BGPで経路を交換する相手 ピア（ネイバー）。異なるAS間なら eBGP、同じAS内なら iBGP
BGPルートリフレクタのループ防止 クラスターID / CLUSTER_LIST と ORIGINATOR_ID（R6午後II）
VRRPで仮想ルータを識別する番号 VRID。端末は 仮想IPアドレスをGWに設定し、仮想MACアドレスへ送る（R4午後II）
VRRPの通常時 / 障害時の役割 マスターが転送、故障時はバックアップが引き継ぐ
1か所の故障で全体が止まる構成要素 SPOF（単一障害点）（H24午後II）

BGP・VRRP・OSPF

4. Web・TLS・メール・認可

問い 答え
クライアントの代理で外部へ / サーバ側の入口で内部へ フォワードプロキシ / リバースプロキシ（H30午後I）
HTTP/2で複数の要求を1本のTCP接続上で扱う単位 ストリーム。各フレームは ストリームID で所属を示す（R5・R7午後I）
HTTP/2でメソッドを示す疑似ヘッダ :method。パスは :path、応答コードは :status（R5午後I）
TLSでクライアント提案 / サーバ選択を運ぶ ClientHello / ServerHello（過去問表記：Client_Hello / Server_Hello、H29午後I）
メール投稿者の認証 / 通信のTLS化 SMTP-AUTH / STARTTLS（H28午後I）
SMTPエンベロープの送信元 MAIL FROM。本文の From: ヘッダとは別（R6午後II）
送信元IPの検証 / 電子署名 / From:との整合・方針 SPF / DKIM / DMARC
OAuth 2.0でAPI要求に使う / 再取得に使う アクセストークン / リフレッシュトークン。後者は認可サーバへ送る（H30午後II）

プロキシ・HTTP/2・TLS・メール認証・OAuth

5. VPN・セキュリティ

問い 答え
IKEv2で制御通信を保護 / IPsecデータ通信を保護 IKE SA / Child SA。Child SA は ESP または AH 用（R4午後I）
IPsecで暗号化もできる / 認証が中心 ESP / AH。ESPのIPプロトコル番号は 50、AHは 51
既知の攻撃パターンで検知 / 通常時との差で検知 シグネチャ検知 / アノマリ検知（H27午後I）
IDSが他端末宛ての受信フレームも扱う / スイッチが監視先へ複製する プロミスキャスモード / ポートミラーリング（H27午後I）
WebアプリをHTTP要求の内容で守る WAF。IP・ポート中心のFW、侵入検知・防御のIDS/IPSと役割を区別

IKEv2・IDS/IPS・WAF

6. LAN・無線・PoE

問い 答え
VLANをEthernetフレームに載せる IEEE 802.1Qタグ。EtherTypeは 0x8100（H25午後I）
ループを防ぎ、冗長リンクの転送先を選ぶ STP/RSTP。ルートブリッジからの距離とポートの役割を見る（R3午後II）
複数リンクを論理的な1本に束ねる LAG。動的な合意には LACP を使う（R1午後I）
無線の複数チャネルを束ねて帯域を広げる / 複数アンテナを使う チャネルボンディング / MIMO（H24午後I）
3系統の無線を同時利用 / 有線収容を2.5G・5Gに高速化 トライバンド / マルチギガビットイーサネット（R5午後I）
PoEの給電側 / 受電側 PSE / PD（H24午後I）
PoE / PoE+ / PoE++ の規格 IEEE 802.3af / 802.3at / 802.3bt（R5・R7午後I）

PoE・無線LAN・マルチギガビット

7. 監視・仮想化・SDN・音声／IoT

問い 答え
SNMPで管理情報の定義 / 個別の識別子 / 自発的な通知 MIB / OID / Trap（R1午後I）
ログの転送 / 機器の簡易ファイル転送 Syslog / TFTP（R4・H23午後I）
OpenFlowでスイッチ→制御器 / 制御器→スイッチへパケット指示 Packet-In / Packet-Out。フロー表を更新するのは Flow-Mod（H29午後II）
VXLANの論理ネットワーク識別 / EVPNのMAC等の広告 VNI / BGP。EVPNで宛先未学習なら Unknown Unicast（R6午後II）
SIPで登録 / 呼の開始 / 確認 / 終了 REGISTER / INVITE / ACK / BYE（R1午後II）
WebRTCでNAT越しのアドレスを調べる / 中継する STUN / TURN。シグナリングに WebSocket を使う構成がある（H28午後II）
IoTで購読するMQTTメッセージ / 軽量なUDPベースの要求応答 SUBSCRIBE / CoAP（H30・R7午後II）
セルラーIoTの加入者識別 / 接続先ネットワーク指定 SIM / APN（H28午後I・R7午後II）

SNMP・OpenFlow・EVPN/VXLAN・SIP・IoT
